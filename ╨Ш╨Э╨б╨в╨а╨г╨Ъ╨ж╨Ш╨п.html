Инструкция для новичка

Авторский сайт без Visual Studio Code и Node.js

Все действия выполняются в браузере. Для первого просмотра достаточно дважды нажать на файл index.html. Для публикации понадобятся бесплатные аккаунты GitHub и Supabase.

Код уже написан. Вам не нужно печатать его вручную. Все файлы находятся рядом с этой инструкцией.

Часть 2

Как открыть демонстрационный сайт

  1. Распакуйте ZIP.
    Нажмите на архив правой кнопкой мыши → Извлечь всё → Извлечь.
  2. Откройте распакованную папку.
    Найдите файл index.html.
  3. Дважды нажмите на index.html.
    Он откроется в Chrome, Edge или другом браузере.
  4. Проверьте страницы.
    Нажмите «Произведения», «Галерея», «Об авторе».
Пока Supabase не подключён, сайт показывает три демонстрационных произведения. Это нормально.

Часть 3

Как поменять название сайта и имя автора

Вариант до публикации: через Блокнот

  1. Откройте папку js.
  2. Нажмите правой кнопкой по config.js.
  3. Выберите Открыть с помощью → Блокнот.
  4. Найдите строки: 
    siteName: "Чернильный дом",
authorName: "Имя автора",
authorEmail: "author@example.com",
  5. Замените только текст внутри кавычек. Кавычки и запятые оставьте.
  6. Нажмите Файл → Сохранить. Закройте Блокнот.
  7. Обновите сайт клавишей F5.
Не используйте пункт «Сохранить как», если не уверены в настройках. Windows может создать файл config.js.txt, и сайт не увидит его.

Как изменить текст «Об авторе»

Откройте about.html через Блокнот. Найдите видимый русский текст о писателе и замените его. Не удаляйте фрагменты в угловых скобках, например <p> и </p>.

Как заменить фотографию автора

  1. Положите свою фотографию в папку images.
  2. Назовите её простым английским именем, например author.jpg.
  3. Откройте about.html через Блокнот.
  4. Замените images/author-placeholder.svg на images/author.jpg.
  5. Сохраните файл.

Часть 4

Как бесплатно опубликовать сайт через GitHub Pages

После этого сайт получит адрес вида https://ВАШ-ЛОГИН.github.io/.

4.1. Создайте аккаунт GitHub

  1. Откройте сайт github.com.
  2. Нажмите Sign up.
  3. Введите электронную почту, придумайте пароль и логин.
  4. Подтвердите электронную почту.

4.2. Создайте хранилище сайта

  1. После входа нажмите значок + в правом верхнем углу.
  2. Нажмите New repository.
  3. В поле Repository name напишите:
    ВАШ-ЛОГИН.github.io
    Например, при логине varvara-books имя будет varvara-books.github.io.
  4. Выберите Public.
  5. Не ставьте галочку создания README, чтобы хранилище было пустым.
  6. Нажмите Create repository.

4.3. Загрузите файлы

  1. На странице пустого репозитория нажмите ссылку uploading an existing file. Если её нет: Add file → Upload files.
  2. Откройте на компьютере распакованную папку сайта.
  3. Нажмите Ctrl + A, чтобы выделить всё содержимое папки.
  4. Перетащите выделенные файлы и папки в большое поле GitHub.
  5. Прокрутите страницу вниз.
  6. В поле сообщения можно написать Первая версия сайта.
  7. Нажмите Commit changes.
Не загружайте только ZIP-архив. GitHub Pages не распакует его. В корне репозитория должен быть виден файл index.html.

4.4. Включите GitHub Pages

  1. Откройте вкладку Settings вашего репозитория.
  2. В левом меню откройте Pages.
  3. В разделе Build and deployment выберите Deploy from a branch.
  4. В поле Branch выберите main, рядом выберите /(root).
  5. Нажмите Save.
  6. Откройте вкладку Actions. Когда публикация отмечена зелёной галочкой, адрес сайта готов.
  7. Откройте https://ВАШ-ЛОГИН.github.io/.

Часть 5

Как создать базу Supabase

5.1. Создайте проект

  1. Откройте supabase.com.
  2. Нажмите Start your project или Sign in.
  3. Удобнее войти через GitHub.
  4. Создайте организацию, если сервис попросит.
  5. Нажмите New project.
  6. Введите название, например author-library.
  7. Придумайте сложный пароль базы и сохраните его отдельно.
  8. Выберите ближайший регион.
  9. Нажмите кнопку создания проекта.

5.2. Создайте таблицы и защиту

  1. В левом меню Supabase нажмите SQL Editor.
  2. Нажмите New query.
  3. На компьютере откройте файл supabase/schema.sql через Блокнот.
  4. Нажмите Ctrl + A, затем Ctrl + C.
  5. Вернитесь в поле SQL Editor и нажмите Ctrl + V.
  6. Нажмите Run.
  7. Убедитесь, что нет красного сообщения об ошибке.
Этот SQL создаёт таблицы произведений, глав, галереи, публичное хранилище картинок и правила безопасности.

Часть 6

Как подключить сайт к Supabase

6.1. Скопируйте адрес и публичный ключ

  1. В Supabase откройте кнопку Connect в верхней части проекта или Settings → API Keys.
  2. Скопируйте Project URL. Он выглядит примерно так: https://abcdefgh.supabase.co.
  3. Скопируйте Publishable key. Он начинается примерно с sb_publishable_.
Никогда не вставляйте Secret key или старый service_role в сайт. В браузерный файл разрешено помещать только Publishable key. Безопасность обеспечивают правила RLS из schema.sql.

6.2. Измените config.js прямо на GitHub

  1. Откройте свой репозиторий GitHub.
  2. Откройте папку js.
  3. Нажмите файл config.js.
  4. Нажмите значок карандаша Edit this file.
  5. Замените: 
    supabaseUrl: "PASTE_YOUR_SUPABASE_URL_HERE",
supabasePublishableKey: "PASTE_YOUR_PUBLISHABLE_KEY_HERE"
    на ваши данные, например: 
    supabaseUrl: "https://abcdefgh.supabase.co",
supabasePublishableKey: "sb_publishable_ВАШ_КЛЮЧ"
  6. Нажмите Commit changes.
  7. В открывшемся окне снова нажмите Commit changes.
  8. После завершения новой публикации обновите сайт.

Часть 7

Как создать аккаунт автора

7.1. Укажите адрес сайта в Supabase

  1. В Supabase откройте Authentication.
  2. Откройте URL Configuration. В некоторых версиях интерфейса этот пункт находится внутри Authentication → Settings.
  3. В поле Site URL укажите https://ВАШ-ЛОГИН.github.io/.
  4. В список Redirect URLs добавьте https://ВАШ-ЛОГИН.github.io/admin.html.
  5. Сохраните изменения.

7.2. Создайте пользователя

  1. Откройте Authentication → Users.
  2. Нажмите Add user.
  3. Выберите Send invitation. Если интерфейс показывает вариант Create new user, можно выбрать его и сразу задать пароль.
  4. Введите свою электронную почту.
  5. Откройте письмо Supabase и завершите создание пароля.

7.3. Дайте аккаунту права автора

  1. На компьютере откройте файл supabase/make-admin.sql через Блокнот.
  2. Дважды замените YOUR_EMAIL@example.com на почту созданного пользователя.
  3. Скопируйте весь код.
  4. В Supabase откройте SQL Editor → New query.
  5. Вставьте код и нажмите Run.
  6. В таблице результата должно появиться значение true в столбце is_admin.

7.4. Войдите

  1. Откройте https://ВАШ-ЛОГИН.github.io/admin.html.
  2. Введите почту и пароль.
  3. Нажмите Войти.

Часть 8

Как пользоваться панелью автора

Добавление книги или рассказа

  1. Откройте вкладку Произведения.
  2. Нажмите + Новое произведение.
  3. Напишите название.
  4. Поле slug можно оставить пустым — адрес создастся автоматически.
  5. Выберите вид: книга, рассказ или иллюстрированный рассказ.
  6. Добавьте жанр, описание и обложку.
  7. Пока работа не готова, оставьте состояние Черновик.
  8. Нажмите Сохранить.

Добавление главы

  1. Перейдите во вкладку Главы.
  2. В выпадающем списке выберите произведение.
  3. Нажмите + Новая глава.
  4. Введите название и номер главы.
  5. Кнопка + Текст добавляет большой текстовый блок.
  6. + Заголовок добавляет заголовок внутри главы.
  7. + Цитата добавляет выделенную цитату.
  8. + Изображение загружает иллюстрацию между текстовыми блоками.
  9. Стрелки ↑ и ↓ меняют порядок блоков, крестик удаляет блок.
  10. Поставьте флажок Опубликовать главу и сохраните.

Публикация произведения

Вернитесь в Произведения, нажмите нужную карточку, выберите состояние Опубликовано и сохраните. Читатели увидят только произведение со статусом «Опубликовано» и только главы с установленным флажком публикации.

Добавление фотографии или рисунка

  1. Перейдите во вкладку Галерея.
  2. Нажмите + Новое изображение.
  3. Введите название и описание.
  4. Выберите изображение.
  5. Поставьте флажок Опубликовать.
  6. Нажмите Сохранить.

Часть 9

Как менять код прямо на GitHub

  1. Откройте нужный файл в репозитории.
  2. Нажмите значок карандаша.
  3. Измените текст.
  4. Нажмите Commit changes.
  5. Подтвердите кнопкой Commit changes.

Для замены изображения откройте папку images → Add file → Upload files. После загрузки используйте точное имя нового файла в HTML.

Материалы, добавленные через панель автора, хранятся в Supabase. Для них редактировать GitHub не требуется.

Часть 10

Частые ошибки

На сайте ошибка 404

  • Проверьте, что файл index.html находится в корне репозитория.
  • Проверьте Settings → Pages: branch main, folder /(root).
  • Посмотрите вкладку Actions: публикация должна завершиться без красного крестика.

Панель пишет «Сначала подключите Supabase»

  • Откройте js/config.js на GitHub.
  • Убедитесь, что оба значения PASTE_... заменены.
  • Проверьте кавычки и запятые.

Ошибка входа

  • Проверьте почту и пароль.
  • Убедитесь, что подтвердили приглашение Supabase.
  • Повторно выполните make-admin.sql с правильной почтой.

Ошибка загрузки изображения или RLS

  • Повторно выполните весь schema.sql.
  • Проверьте, что аккаунт имеет is_admin = true.
  • Загружайте JPG, PNG, WEBP или GIF размером до 10 МБ.

Изменение не появилось

  • Откройте вкладку GitHub Actions и проверьте последнюю публикацию.
  • На сайте нажмите Ctrl + F5.

Финальная проверка

  • Сайт опубликован и открывается.
  • В Supabase выполнен schema.sql.
  • В config.js вставлены Project URL и Publishable key.
  • Создан пользователь автора.
  • Выполнен make-admin.sql.
  • Вход через admin.html работает.
  • Тестовое произведение отображается в каталоге.

Интерфейс GitHub или Supabase иногда меняет названия кнопок. Ищите максимально близкие пункты: Repository/репозиторий, Settings/настройки, Pages/страницы, Authentication/аутентификация, Users/пользователи, SQL Editor.
